## Known limitations

1. **Structured Version / Qualifiers / Provider Guid** are not separate TimelineEvent fields; they appear inside **Raw Event XML** when Windows provides them.
2. **Wevtapi subscribe resume bookmark** remains explicitly deferred (doc 07 / 34 / 36).
3. **Multi-step display recovery chains** (driver → DWM → recovery) are not correlated until additional Event IDs are documented in doc 37.
4. **100k live UI scroll FPS** is gated by synthetic CPU tests + architecture (virtualization, lazy XML); maintainer should spot-check scroll smoothness after raising the retention cap.
5. **Incidents are not persisted as objects** — they reappear only while matching events remain in the in-memory Timeline buffer.
6. **Security-channel intelligence** only surfaces when the Security log is readable under the current user.
7. **Process name** is best-effort from PID resolution; empty when Windows does not allow resolution.
8. Theme redesign work (if stashed) remains **out of R2** and must not be mixed into the R2 close commit set.
