## 1. Incident timeline

When deterministic correlation rules match a known sequence (provider + Event IDs + time window), collapse into one **incident** row:

Example: “Display Driver Reset” → expand → driver event → display restart → DWM → recovery.

Rules live in documented tables (doc + code). No clustering without a rule match. Ungrouped events remain flat.

## 2. Root-cause hints

When a matched incident/rule set exists, details show:

| Field | Source |
|-------|--------|
| Possible cause | Rule `cause` string (static, documented) |
| Confidence | Rule enum: High / Medium / Low (static) |
| Related events | Linked `event_id`s from correlation |
| Suggested next step | Existing recommendation / rule next-step |

Empty when no rule matches. Never LLM / free-form invention.

## 3. Timeline details (Event Viewer parity)

Details panel exposes when Windows provides them:

Provider, Channel, Computer, Event ID, Level, Opcode, Keywords, Task, Process, PID, SID, Record ID, Activity ID, Correlation/Related Activity ID, formatted message, **Raw Event XML** (lazy-loaded).

Missing values show unavailable — never placeholders pretending to be data.

## 4. Event links

From details / incident: Previous related, Next related, Same provider, Same process (if PID known), Same incident.

Navigation selects/scrolls within the in-memory timeline — no fabricated peers.

## 5. Timeline metadata badges

Per row / details: Captured / Observed / Imported / Live / Bookmarked / Pinned / Correlated / Generated by rule — only when true.

## 6. Export

Timeline JSON + CSV include applied filters, bookmark/pin flags, correlation/incident ids, and available metadata columns. No silent drop of user marks.

## 7. Search

Case-insensitive over: provider, event ID, computer, message, XML (when loaded), keyword, process name, PID. Composable with chips/filters.

## 8. Performance

Virtualized list (`ListView.builder` / existing patterns). Stable `event_id` keys. Details/XML on demand. Avoid rebuilding unchanged tiles. Target smooth scroll with **100,000+** retained events (settings max may raise; memory honesty documented).

## 9. Validation

Spot-check against Event Viewer for sample Event IDs/providers/channels. Document every correlation / RCA rule with Microsoft citations. Expand intelligence rules only with documented IDs; publish pre/post counts (baseline **38**).

## Wire / IPC (additive)

Extend `TimelineEvent` with optional fields (examples): `task`, `opcode`, `keywords`, `has_process_id`/`process_id`, `process_name`, `user_sid`, `activity_id`, `related_activity_id`, `level_name`, optional `raw_xml` **or** separate lazy `GetTimelineEventXml` request keyed by channel+record_id.

Prefer **lazy XML** IPC to keep 100k lists memory-safe.
